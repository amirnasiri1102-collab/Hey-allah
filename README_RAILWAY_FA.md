# Hey-allah / Nobati — نسخه اصلاح‌شده برای Railway

این بسته بر اساس فایل سورسی ساخته شده که در گفتگو آپلود شد. قابلیت‌های قبلی حفظ شده‌اند؛ هیچ تابع سطح‌بالای قبلی حذف نشده است.

## راه‌اندازی روی Railway

1. محتوای این پوشه را در پروژه Railway قرار بده یا به مخزن GitHub خودت push کن.
2. در بخش **Variables** این متغیرها را تعریف کن:

   | نام متغیر | وضعیت |
   |---|---|
   | `BOT_TOKEN` | **ضروری** — توکن ربات مدیریت را فقط اینجا به‌عنوان Secret قرار بده. |
   | `TIIMER_API_ID` | اختیاری — مقدار پیش‌فرض داخل سورس وجود دارد؛ فقط برای جایگزینی تنظیم کن. |
   | `TIIMER_API_HASH` | اختیاری — مقدار پیش‌فرض داخل سورس وجود دارد؛ فقط برای جایگزینی تنظیم کن. |

3. در بخش **Volumes** یک Volume بساز و Mount Path را روی `/persistent` بگذار. سورس به‌صورت خودکار متغیر `RAILWAY_VOLUME_MOUNT_PATH` را می‌خواند و اطلاعات را در مسیرهای زیر نگه می‌دارد:
   - `/persistent/data`
   - `/persistent/sessions`
4. تعداد Replica را روی **1** نگه دار. یک فایل Session را هم‌زمان در دو Replica یا روی Railway و یک سرور/دستگاه دیگر اجرا نکن.
5. Deploy را اجرا کن. دستور شروع از `Procfile` خوانده می‌شود: `python -u eliot_bot.py`.

`PORT` را خود Railway تعیین می‌کند؛ سرویس HTTP داخلی سورس همان پورت را استفاده می‌کند.

## اصلاحات انجام‌شده

- اضافه‌شدن ذخیره‌سازی پایدار Railway و انتقال امن فایل‌های قبلی `data` و `sessions` به Volume، بدون بازنویسی فایل‌های موجود.
- قفل مجزا برای چرخه اتصال هر Session تا Worker و Protected Client به‌طور هم‌زمان یک فایل SQLite را باز نکنند.
- استفاده مجدد از کلاینت Session فعال در بررسی سلامت و بخش مدیریت 2FA، به‌جای ساخت کلاینت هم‌زمان روی همان فایل.
- بستن اتصال Telethon پس از خروج غیرمنتظره Worker و تلاش مجدد کنترل‌شده برای اتصال.
- اضافه‌شدن ناظر اتصال مجدد برای ربات مدیریت و ربات‌های گروهی.
- اصلاح پشتیبانی از پورت اختصاصی Railway.
- اصلاح تشخیص خطاهای خالی از متن، از جمله `TimeoutError` در لاگ Session Guard، و افزودن فاصله افزایشی بین اسکن‌های ناموفق.
- اصلاح پردازش متن ایموجی‌های ویژه با رعایت parse mode فعال.
- اصلاح ذخیره snapshot دیتابیس برای جلوگیری از خواندن هم‌زمان دیکشنری در حال تغییر.
- بازسازی primitiveهای asyncio هنگام راه‌اندازی مجدد main در همان پردازش.
- رفع خطای جایگزینی newline در پیام خطای پنل پیشرفت.

## نکته مهم درباره خطاهای پیام قدیمی تلگرام

خطای `very old message ID` فقط با تغییر کد قابل رفع قطعی نیست. ساعت سرور، استفاده هم‌زمان از یک فایل Session در چند پردازش، یا پروکسی ناپایدار هم می‌توانند باعث آن شوند. قبل از Deploy نسخه جدید، اجرای قدیمی را متوقف کن و مطمئن شو همان Session در جای دیگری باز نیست.

## محافظت از Sessionها

فایل‌های `.session` و فایل پشتیبان شامل اعتبارنامه‌های ورود تلگرام هستند. آن‌ها را در مخزن عمومی یا برای افراد دیگر ارسال نکن. قابلیت پشتیبان‌گیری خودکار پروژه همچنان حفظ شده و آرشیو پشتیبان ممکن است Sessionها را دربر بگیرد.
